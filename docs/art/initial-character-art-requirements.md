# 初始角色“人”美术与动作需求

## 目标

把战场上的初始角色从“圆形底座中的人字图标”升级为可读、可运动、可承载装备的角色形体。玩家应先看到身体带动手臂和刀完成挥砍，水墨轨迹只作为动作余韵，不再代替角色动作。

本需求只定义初始角色“人”。后续角色和其他武器应复用同一套分层、锚点与动作接口。

## 已确定的设计

- 视角：轻度俯视的纸偶式角色，适配当前俯视战场。
- 造型：`人`字的两道笔画构成躯干与双腿，再长出头部、双臂和握刀的手。
- 表情：米纸色圆头，两个墨点眼睛，无嘴；情绪主要通过眼睛、重心和姿态表达。
- 服装：短款宽袖，不遮住“人”字身体结构，不增加盔甲、披风或复杂配饰。
- 展示：战斗中始终保持正面可读，不因向上移动显示背面，也不通过镜像把刀换到另一只手。
- 攻击指向：鼠标决定眼神、上半身和刀的目标方向；WASD 只决定行进与步态。
- 装备：刀是独立素材层，不得烘焙进身体或手臂。
- 动作气质：轻快、克制、有书法提按感，不做沉重武将动作。
- 普攻：约 280ms 的快速横斩，有预备、踏步、有效帧与收势。

## 游戏内尺寸

游戏逻辑画布为 `1024 × 768`，运行时等比缩放。

| 项目 | 规格 |
|------|------|
| 单个源素材画布 | 256 × 256 px，RGBA 透明 PNG |
| 游戏内素材缩放 | 约 0.5 倍 |
| 角色可见高度 | 源图 140–152 px；游戏内约 70–76 逻辑像素 |
| 角色碰撞半径 | 保持 27 逻辑像素，不随美术外轮廓改变 |
| 刀身长度 | 源图约 66–76 px；游戏内约 33–38 逻辑像素 |
| 最大挥砍外沿 | 距角色逻辑中心约 100–112 逻辑像素 |
| 脚底基线 | 源画布 `y = 206` |
| 角色根锚点 | 源画布 `(128, 164)` |

所有部件使用同一个 256 × 256 画布和角色根坐标。各关节及刀柄有各自锚点；打包 atlas 时可裁掉透明区域，但必须保留原始 `sourceSize`、`spriteSourceSize` 和锚点信息。

## 视觉语言

- 线条使用有粗细变化的毛笔笔触，边缘允许少量飞白和自然渗墨。
- 主体色为墨黑、深灰和暖米白，袖口可使用低饱和灰绿色，与当前游戏场景协调。
- 不使用纯黑粗描边、霓虹光、金属高光或厚重 3D 体积。
- 头部和衣袖可以有轻微纸纤维纹理，但不得影响小尺寸轮廓。
- 在 76 逻辑像素高的显示尺寸下，头、两臂、`人`字双腿和刀必须仍能区分。
- 不在角色素材中绘制影子、挥砍轨迹、受击闪光、火焰或墨点粒子；这些属于独立效果层。

## 分层结构

运行时从后向前按以下顺序组合；向上指向时持刀臂和刀移到头部后面：

1. `shadow`：程序绘制的地面椭圆影，不需要出图。
2. `rear_arm`：远离镜头的手臂和袖子。
3. `body`：完整的“人”字躯干与双腿。
4. `head`：圆头和两点眼睛。
5. `front_upper_arm`：靠近镜头的上臂和宽袖。
6. `front_forearm`：以肘为轴的前臂，不含手掌。
7. `weapon_knife`：刀柄锚点固定到手掌握点。
8. `hand_front`：以腕为轴的手掌，覆盖刀柄的一小段。
9. `vfx`：程序生成的细水墨拖尾、墨点和受击闪光。

战斗运行时需要以下透明 PNG：

```text
ren_body_front.png
ren_head_front.png
ren_rear_arm_front.png
ren_front_upper_arm_front.png
ren_front_forearm_front.png
ren_hand_front.png
ren_weapon_knife.png
```

已完成的背面和侧面素材保留在源目录作历史参考，但战斗场景不加载或切换到它们。持刀手固定在角色同一侧，向左攻击时自然跨过身体。

## 关节与锚点

坐标均基于 256 × 256 正面源画布。握点以实际可见手掌为准，不能只依照概念图上的理论位置。

| 锚点 | 正面坐标 | 用途 |
|------|----------|------|
| 根锚点 | (128,164) | 角色逻辑位置 |
| 头部中心 | (128,78) | 呼吸和受击摆动 |
| 后肩 | (108,112) | 后臂旋转 |
| 前肩 | (148,112) | 持刀上臂旋转 |
| 前肘 | (164,137) | 前臂旋转 |
| 前腕 | (161,149) | 手掌旋转 |
| 手掌握点 | (162,157) | 手掌与刀柄连接点 |
| 刀柄锚点 | (38,128) | `weapon_knife` 自身坐标 |

交付时另附一张 `ren_anchor_guide.png`：显示完整中立姿势、上述锚点十字和坐标标签。该图仅供接入参考，不进入游戏。

## 朝向规则

- 身体始终使用正面素材；上下左右移动只改变步态和重心。
- 鼠标相对角色的位置决定攻击指向。鼠标静止、角色移动时仍须每帧重算；鼠标贴近角色中心时保留最后有效指向。
- 待机和移动时上半身、手臂、刀平滑跟随鼠标，身体保持正面可读。
- 攻击开始后锁定本次指向；翻滚和受击期间也不随鼠标突然翻转，动作结束再回到当前指向。
- 不镜像整个人物或切换持刀手；指向上方时让手臂和刀适当处于头部后方。

## 动作规格

### 待机 `idle`

- 循环时长：1200ms。
- 身体上下浮动不超过 2 逻辑像素。
- 头部比身体延迟约 80ms，形成柔和呼吸感。
- 前后手臂有 2–3° 的自然摆动；刀尖轻微下沉。
- 每 3–5 个循环允许眨眼一次，不要求固定频率。

### 移动 `move`

- 步态循环：约 500ms。
- “人”字两道腿笔画通过轻微剪切、缩放和左右重心变化表现踏步，不把字拆成失去辨识度的普通双腿。
- 身体垂直起伏不超过 3 逻辑像素，头部保持相对稳定。
- 双臂小幅反向摆动；持刀手臂摆幅更小，刀尖保持安全朝外。
- 移动开始和停止各有约 80ms 的重心过渡，避免瞬间滑行。
- 向上行进也保持正面；移动方向与攻击指向可完全相反。

### 刀普攻 `attack_knife`

总时长 280ms，冷却仍可保持约 330ms。

| 阶段 | 时间 | 表现 | 规则 |
|------|------|------|------|
| 预备 | 0–70ms | 重心下沉，身体向挥刀反方向微扭，手臂收刀 | 不造成伤害 |
| 挥出 | 70–112ms | 前脚踏出，上臂带动前臂和刀加速 | 不造成伤害 |
| 有效帧 | 112–155ms | 刀刃经过鼠标方向，身体完成最大扭转 | 只结算一次伤害 |
| 收势 | 155–280ms | 刀尖减速，身体与重心回正 | 155ms 后可翻滚取消 |

- 攻击期间移动速度为正常速度的 45%。
- 挥刀由身体轻扭带动肩，肩带上臂、肘带前臂、腕带手掌和刀；手掌握点始终与刀柄锚点重合。不能让整组只绕肩旋转，也不能让刀独自在静止手掌里转动。
- 手先收向身体，再随挥出向目标伸展，收势回到待机握刀位置。持刀手不因攻击左右方向切换。
- 刀从瞄准方向后方约 `-70°` 扫至前方约 `+65°`。
- 伤害判定必须在刀进入有效帧时触发，不能在点击当帧触发。
- 原有实心半圆删除，替换为紧随刀尖的细墨拖尾；拖尾宽度前粗后细，并在约 140ms 内消散。
- 墨迹只说明速度和方向，不得比角色和刀更醒目。

### 翻滚 `dodge`

- 总时长：260ms，与当前移动规则一致。
- 0–40ms：身体压缩，头和手臂向内收。
- 40–200ms：身体压低并侧倾，保持正面可读；刀贴近身体，避免像独立物体漂浮或整个人转一整圈。
- 200–260ms：展开并恢复朝向。
- 使用 2–3 层短寿命淡墨残影，不能只降低整体透明度。

### 受击 `hurt`

- 总时长：160ms。
- 身体沿伤害反方向后仰，头部比身体多延迟 20–30ms。
- 眼睛短暂收紧，刀和持刀臂随惯性滞后。
- 身后飞出少量墨点；墨点不烘焙进角色素材。
- 保留镜头轻震，但透明闪烁只作为辅助反馈。

### 死亡 `death`

- 建议时长：500–650ms。
- 身体的“人”字笔画失去支撑并化为向下晕开的墨迹，刀先落地。
- 结算遮罩应在死亡主体动作结束后出现，不要立即盖住角色。

## 动作状态与打断

优先级从高到低：`death > hurt > dodge > attack > move > idle`。

- `attack` 在 155ms 前不能被普通移动或下一次攻击打断。
- `attack` 从 155ms 起可以被 `dodge` 打断。
- `hurt` 可以打断 `idle`、`move` 和 `attack`，不能打断 `death`。
- `dodge` 无敌期间不进入 `hurt`，但仍可播放近失墨点反馈。
- 每次攻击的有效帧只允许结算一次，不因帧率下降重复命中。

## AI 生图工作流

不要让生成模型一次性输出完整 spritesheet。现有正面角色已经确定，新增或调整局部素材时按以下顺序保持一致性：

1. 使用现有正面中立姿势作为角色参考，不重新设计身份或服装。
2. 需要时单独重绘上臂、前臂或手掌，使肩、肘、腕和握点与参考图对齐。
3. 刀保持独立素材，不画在手臂上。
4. 将部件放入统一 256 × 256 画布，人工校正实际可见手掌、刀柄和透明边缘。

## 素材验收标准

- [ ] 透明背景包含真实 alpha，不是白底或棋盘格图案。
- [ ] 正面部件的角色身份、比例、服装和笔触一致。
- [ ] 缩小到游戏尺寸后仍能读出“人”字、头、双臂和刀。
- [ ] 根锚点、肩、肘、腕、可见手掌握点和刀柄锚点对齐。
- [ ] 向左跨身与向上举刀时手和刀仍然相连，头部遮挡正确。
- [ ] 身体与手臂素材不包含刀、阴影、拖尾、火焰或受击效果。
- [ ] 刀柄可在握点处自然连接，旋转时不会明显脱手。
- [ ] 角色外缘没有白边、深色矩形底或半透明脏像素。
- [ ] 所有源图都是 256 × 256 RGBA PNG，文件名与清单一致。

## 游戏接入验收标准

- [ ] 待机时能感知呼吸、眨眼和轻微重心变化。
- [ ] 移动不是整张图片平移，身体存在明确步态。
- [ ] 攻击由身体扭转、手臂挥动和刀刃运动共同完成。
- [ ] 上臂、前臂、手掌和刀各随对应关节运动，刀柄始终贴住实际可见手掌。
- [ ] 向上移动不露背；鼠标静止而角色移动时攻击指向仍更新。
- [ ] 伤害只在刀经过目标的有效帧结算一次。
- [ ] 原有实心半圆不再承担主要攻击表现。
- [ ] 翻滚有收身、滚动、展开和残影过程。
- [ ] 受击方向与角色后仰方向一致。
- [ ] 角色视觉变化不改变现有 27px 逻辑碰撞半径。
- [ ] 1280×900 与窄屏 FIT 缩放下角色和刀均清晰，无 UI 遮挡。
