# ADR-0013: 手写汉字识别与毛笔书法宣纸造字台

## 状态
已采纳 (Accepted)

## 背景
此前造字台采用 3×3 米字格槽位点选摆放笔画的模式（ADR-0012）。虽然解决了拓扑匹配，但缺乏书法写字的自然沉浸感与自由度。用户期望将造字台升级为**真实手写**，在画板上挥毫书写汉字，并通过开源汉字手写识别库进行实时识别与构筑。

在方案选型上：
1. **云端 OCR API（百度/腾讯/Google）**：精度高，但依赖网络、延迟高且有 API 配额与费用风险。
2. **TensorFlow.js 深度学习模型（如 @zh-keyboard/recognizer）**：功能完备，但模型权重文件大（>30MB），初始化慢且消耗 WebGL/GPU 资源。
3. **开源笔画拓扑匹配库（HanziLookupJS + MMAH 9507 字数据集）**：
   - 纯原生 JavaScript 实现，核心库仅 12KB；
   - 数据文件 `mmah.json` 仅 807KB，涵盖 9,507 个中文常用汉字及异体字；
   - 纯前端离线运行，单次多笔画识别耗时仅 5~15ms；
   - 基于笔画走向、长度与中心点拓扑评分，对手写笔顺与形态具有良好的容错度。

## 决策
1. **采用 HanziLookupJS + MMAH 数据集**：
   - 将 `hanzilookup.min.js` 部署至 `public/libs/`，`mmah.json` 部署至 `public/assets/data/`；
   - 在前端封装为 `HandwritingService` 单例，于冷启动（BootScene）异步静默拉取与解码，无需用户等待；
   - 识别结果返回 Top 6 候选汉字与置信度。

2. **宣纸毛笔书法交互画板（BaseScene）**：
   - 造字台主界面提供米字格宣纸手写板，支持鼠标/触控连续运笔绘制浓淡水墨线条；
   - 支持【撤销单笔】（重新识别）与【清空画板】；
   - 抬笔时即时触发识别，并在画板旁以书法印章/玉牌形式展示候选汉字；
   - 玩家可自由点击切换候选汉字。

3. **资源校验与凝符规则**：
   - 识别出的汉字若收录在游戏词库中，即时显示其字性（兵刃字/属性字/基础字）与词缀加成；
   - 比对玩家仓中拥有的笔画（横、竖、撇、捺、点、折）与该字标准笔画配方；
   - 笔画充足即可点击【凝字成符】扣减笔画入库，供铸武台组词锻造。

## 后果
- 极大增强游戏作为“造字”主题的核心文化韵味与游戏乐趣；
- 离线稳定运行，零外部依赖，极佳的性能与响应速度；
- 扩展新汉字只需在 GameState 配置表新增词条与笔画配方即可，手写识别引擎原生支持万字识别。
