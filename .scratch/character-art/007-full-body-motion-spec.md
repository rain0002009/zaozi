# 全身动作与自然步态

## Problem Statement

玩家觉得角色动作僵硬，尤其是攻击、闪避、受击和死亡时下半身几乎没有参与。走路时两条整腿只绕髋部做刚体摆动，腿部轮廓高度重叠，摆动后容易出现类似重影的双边缘；步态又由绝对时间驱动，与实际移动距离脱钩，所以脚底会滑。

当前动作实现还存在三个连续性问题：攻击期间角色可以平移但普通步态很快停止，造成下盘待机式滑行；鼠标换侧或连击换侧时整体镜像会让支撑脚瞬移；闪避、受击和死亡主要依赖整体容器旋转、压缩或淡出，缺少真实的支撑、失衡和倒地关系。

## Solution

保留初始角色“人”的身份、脸部、服装、配色、侧身视角、游戏尺寸和战斗规则，将角色形体升级为可表达膝、踝和脚底支撑的分段纸偶。每条腿拆为大腿、小腿和脚，新增独立衣摆；远侧腿使用略低明度但保持不透明，避免被看成残影。

建立一个由关键姿势数据与程序步态求解组成的角色动作模块。关键姿势定义攻击、闪避、受击和死亡的全身受力关系；步态根据实际位移距离推进，维护支撑脚、落脚位置和方向切换相位。普通转身和连击换侧立即响应操作，但由上半身先转向、下盘再完成支撑脚转换，不瞬间镜像整个角色。

武器只提供玩法数值、招式时序和动作名称，角色动作模块负责将动作事件、实际位移和时间转换为完整 rig 姿势。测试通过该模块接口验证外部动作结果，再由一个真实战斗场景回归输入、判定、状态时序和最终画面。

## User Stories

1. 作为玩家，我希望角色拥有清楚的前后腿关系，以便我能看懂角色当前的支撑脚。
2. 作为玩家，我希望膝盖和脚踝会随动作弯曲，以便角色不像两张刚性图片。
3. 作为玩家，我希望脚掌在支撑期间保持落地点，以便角色不会在地面滑行。
4. 作为玩家，我希望走路步频随实际移动距离推进，以便速度变化不会造成脚步与位移错位。
5. 作为玩家，我希望起步从稳定姿势进入，以便角色不会从任意步态相位突然开始走。
6. 作为玩家，我希望停步时能在短时间内收脚，以便角色不会被硬暂停在半步姿势。
7. 作为玩家，我希望前进使用正常的后脚推动和前脚落地，以便方向感自然。
8. 作为玩家，我希望后退时仍保持迎敌姿势，以便移动方向不会错误地改变攻击侧。
9. 作为玩家，我希望纵向移动使用窄幅侧移步，以便双腿不会过度交叉。
10. 作为玩家，我希望斜向移动能在相邻步态间平滑混合，以便不会跳到另一套动作。
11. 作为玩家，我希望方向切换保留当前支撑脚，以便改变移动方向时脚底不瞬移。
12. 作为玩家，我希望角色被边界阻挡时停止推进步态相位，以便不会原地踏步。
13. 作为玩家，我希望第一刀的前脚支撑和双膝下沉清楚可见，以便斜劈有下盘发力。
14. 作为玩家，我希望第二刀把重心转移到后脚，以便反向上撩不是只动手臂。
15. 作为玩家，我希望第三刀由后脚蹬地并以前脚踏出，以便终结招有重量感。
16. 作为玩家，我希望攻击期间不会重新播放普通走路循环，以便招式脚步和攻击轨迹一致。
17. 作为玩家，我希望攻击中的有限移动仍有相应的下盘动作，以便角色不会身体平移而腿保持待机。
18. 作为玩家，我希望鼠标换侧时攻击响应立即，以便角色不会感觉输入延迟。
19. 作为玩家，我希望普通转身在短时间内完成，以便支撑脚不会瞬间换位。
20. 作为玩家，我希望连击换侧时上半身先转、下盘后跟，以便连续攻击不会产生脚部瞬移。
21. 作为玩家，我希望单招期间攻击侧保持锁定，以便挥刀中途不会突然镜像。
22. 作为玩家，我希望闪避沿实际移动方向压低重心和跨步，以便视觉方向与位移一致。
23. 作为玩家，我希望没有移动输入时闪避才使用鼠标方向，以便默认行为可预测。
24. 作为玩家，我希望闪避撞到边界时提前收势，以便角色不会表现出不存在的滑行。
25. 作为玩家，我希望受击时身体向冲击反方向失衡并由后脚支撑，以便受击方向可读。
26. 作为玩家，我希望受击时头和持刀臂略晚于躯干回弹，以便冲击具有惯性。
27. 作为玩家，我希望死亡先失去腿部支撑再倒下，以便死亡不是简单的整体压扁。
28. 作为玩家，我希望死亡倒地方向继承最后一次冲击，以便结果与受击方向一致。
29. 作为玩家，我希望短刀先脱手或落地，以便死亡动作有清晰的先后关系。
30. 作为玩家，我希望攻击被受击打断时从当前姿势进入受击，以便不会跳回待机。
31. 作为玩家，我希望闪避和受击结束时从当前落脚状态过渡，以便动作连续。
32. 作为玩家，我希望暂停后恢复保持动作相位，以便画面不会跳帧。
33. 作为玩家，我希望远侧腿更暗但不是半透明，以便前后层次清楚且没有残影感。
34. 作为美术制作者，我希望所有腿部部件共用一致的锚点和隐藏重叠区，以便弯曲时不会出现裂缝。
35. 作为美术制作者，我希望保留当前角色身份和上半身资产，以便本次工作聚焦动作质量。
36. 作为美术制作者，我希望源素材只有一个可编辑真源，以便不会再次修改错误的运行时副本。
37. 作为开发者，我希望武器不直接保存角色关节角度，以便新增武器不会复制人体实现。
38. 作为开发者，我希望动作模块以小接口提供完整姿势，以便复杂步态细节集中维护。
39. 作为开发者，我希望测试通过动作模块接口观察结果，以便测试不依赖私有关节变量。
40. 作为开发者，我希望浏览器回归覆盖真实战斗场景，以便输入、动画和判定能一起验证。
41. 作为维护者，我希望旧整腿素材和不可复现脚本在新 rig 验收后退役，以便项目不会保留两套动作路径。

## Implementation Decisions

- 采用 14 个可见角色与武器部件：远侧大腿、远侧小腿、远侧脚、远侧手臂、躯干、头部、近侧大腿、近侧小腿、近侧脚、衣摆、持刀上臂、持刀前臂、手掌和短刀；地面影与 VFX 继续由程序生成。
- 每条腿以髋、膝、踝和脚底组成连续关节链，素材保留髋、膝、踝的隐藏重叠区；衣摆作为髋部遮挡和少量惯性层。
- 编辑源素材统一使用 1024 × 1024 RGBA 画布；运行时发布素材确定性缩小为 256 × 256 RGBA 画布。编辑源素材是唯一真源，运行时目录只接受构建同步产物。
- 远侧腿使用略低明度与对比度但保持不透明，并置于躯干和近侧腿之后；不使用半透明制造远近关系。
- 角色 rig 定义集中维护部件名称、层序、锚点和默认姿势；素材校验、加载和动作模块共享该定义。
- 角色动作模块是最高测试 seam。它接收动作事件、实际位移和时间，返回完整 rig 姿势，并隐藏步态相位、支撑脚、落脚约束、转身和姿势插值。
- 动画采用混合驱动：攻击、闪避、受击和死亡的全身关键姿势由动作数据定义；普通步态相位按实际位移推进，程序维护支撑脚和落脚位置。
- 步态完整周期约覆盖 110 逻辑像素；起步和停步约 100–120ms，方向切换约 100ms 混合；支撑期脚掌世界位置漂移目标不超过 1.5 逻辑像素。
- 普通移动区分相对当前朝向的前进、后退和纵向侧移；斜向输入在相邻步态之间混合，不改变鼠标控制的攻击侧规则。
- 普通转身约 80ms 完成，攻击侧可以立即更新；上下身和近远腿职责分阶段交换，支撑脚保持连续。
- 连击换侧在下一招开始时读取新的攻击侧；上半身先转向，下盘在预备阶段完成重心与支撑脚转换。
- 第一刀以前脚支撑并屈膝下沉，第二刀把重心转移到后脚，第三刀以后脚蹬地并以前脚完成现有前踏；攻击期间停止普通步态循环。
- 闪避保持现有 260ms 时长、移动速度、无敌窗口和冷却，只改变视觉为沿实际闪避速度方向的压低重心、收刀和跨步滑开。
- 受击保持现有 160ms 时长，从当前姿势以约 30–40ms 进入屈膝失衡姿势；死亡沿最后一次冲击反方向或当前面对方向的侧后方倒下，保持现有结算时序。
- 武器连击定义保留玩法数值、时序和动作名称，不再直接拥有角色身体关节角度；角色动作模块消费这些动作名称并生成全身表现。
- 保持既有鼠标左右攻击侧、单招锁定、连击输入缓存、三段短刀判定、火球全方向瞄准、移动速度、碰撞半径和所有战斗规则不变。
- 实施完成后一次性切换运行时 rig；新回归通过后删除旧整腿资产、兼容路径和无法重建当前角色的过时生成脚本。

## Testing Decisions

- 角色动作模块使用确定性测试，输入动作事件、实际位移和时间，验证输出姿势的外部性质：步态相位连续、支撑脚漂移、关节连接、方向切换、转身、动作中断和暂停恢复。
- 测试不锁定私有字段、具体插值公式、内部相位变量或单个素材实现；动作模块接口是唯一低层测试接缝。
- 支撑期脚掌世界位置漂移目标不超过 1.5 逻辑像素；髋、膝、踝、肩、肘、腕和刀柄连接误差目标不超过 1 逻辑像素。
- 步态回归覆盖前进、后退和纵向侧移的接触、下沉、经过和抬升四个阶段，并覆盖起步、停步、方向切换、边界阻挡和斜向混合。
- 全身姿势回归覆盖三段攻击的预备、命中和收势，闪避的压低/跨步/收势，受击的失衡/回弹，以及死亡的失去支撑/倒地终态。
- 浏览器级真实战斗回归保留一个完整战斗场景，使用鼠标和键盘输入验证左右攻击侧、单招锁定、连击换侧、闪避方向、受击打断、火球全方向瞄准和战斗判定。
- 浏览器视觉回归覆盖逻辑画布、桌面视口和窄屏视口，分别生成左右朝向、步态周期、攻击、闪避、受击、死亡、转身和连击换侧联系表。
- 视觉验收否决以下情况：支撑脚明显滑动；双腿形成平行双轮廓；关节裂缝或脱节；转身/换侧脚部瞬移；攻击平移而下盘待机；闪避方向与实际位移不一致；受击/死亡仍主要依赖整体旋转、压缩或淡出；远侧腿像半透明残影。
- 构建和类型检查是交付门槛；项目现有浏览器回归脚本作为真实战斗测试先例，扩展后替换只检查旧整腿角度的浅层断言。

## Out of Scope

- 不重画头部、躯干、手臂和短刀主体，不重新设计角色身份、服装、配色或视角。
- 不改变短刀和火球的玩法数值、攻击判定、移动速度、碰撞半径、受击时长、闪避无敌窗口、冷却或死亡结算规则。
- 不制作短刀之外的新武器连击，不处理其他角色或怪物动画。
- 不采用逐像素刀刃碰撞，不制作完整 spritesheet，不建设通用动画编辑器。
- 不保留旧整腿和新分段 rig 的运行时兼容分支。
- 不以整屏像素黄金图替代行为、连接和联系表验收。

## Further Notes

- 本 spec 延续“汉字语义与视觉字形解耦”和“侧身角色与左右近战攻击侧”两项已接受决策。
- 领域术语使用“角色形体”“全身动作姿势”“步态”“闪避”和“招式关键姿势”；“翻滚”只作为旧资料中的历史称呼，不作为新动作名称。
- 现有角色美术需求已经记录分段下肢、距离步态、动作过渡、唯一素材真源和视觉否决条件；本 spec 将其整理为可拆分实施的工程范围。
- 本 spec 的交付顺序是：rig 定义与素材校验 → 分段腿部与衣摆 → 角色动作模块及确定性测试 → 攻击/闪避/受击/死亡接入 → 运行时素材切换 → 浏览器回归与联系表 → 旧路径退役。
- 最终自动测试通过后仍需要项目维护者查看联系表确认动作观感；自动测试不能替代人眼判断。
