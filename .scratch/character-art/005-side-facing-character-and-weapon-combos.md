# 侧身角色与武器连击

## 当前状态

已完成。运行时已切换为九层右侧身纸偶并在左侧攻击时整体镜像；短刀三段连击、固定左右命中扇区、垂直盲区、输入缓存、第三段前踏与反馈均已接入真实战斗场景。

后续动作可读性复查发现，原实现虽然通过握点 IK 改变了肩肘角度，但主要视觉变化仍来自刀和墨迹，手臂与身体的发力不够清楚。现已改为由短刀连击定义显式提供每招的预备、命中与收势关键姿势：第一刀抬臂斜劈、第二刀从低位反撩、第三刀背后蓄力后转体伸臂横斩。上一招收势直接成为下一招起点，角色不在连击中途返回待机。

实测锚点采用统一 256 × 256 画布坐标：根 `(128,164)`、躯干/髋 `(128,135)`、后肩 `(121,89)`、持刀肩 `(128,89)`、肘 `(117,114)`、腕 `(126,135)`、握点 `(126,138)`、刀尖 `(166,138)`。浏览器回归覆盖左右翻转、三段动作与握柄连接、步态、受击/死亡重置、远程全方向瞄准、桌面与窄屏画布；运行命令为 `$env:GAME_URL='http://127.0.0.1:5175/'; node .scratch\character-art\verify-side-combat.cjs`。

动作回归还会检查每招从预备到命中期间的上下臂角度以及肩、肘、腕位移，并生成隐藏短刀和墨迹的 `.scratch/character-art/side-combat-body-poses.png` 联系表。三招必须仅凭身体轮廓仍可区分，不能再以“关节数值略有不同”代替视觉验收。

## Problem Statement

当前角色始终以正面展示，持刀手臂和短刀却会跟随鼠标进行 360° 旋转。当玩家攻击斜上、正上或斜下的敌人时，身体透视、肩肘关系和挥刀轨迹彼此冲突，动作像是刀在角色周围转动，而不是身体带动手臂挥刀。初始角色还必须维持“人”字躯干，这让正常人体、可读步态和模块化动作难以同时成立。

玩家需要一个容易判断朝向、攻击区域和连击阶段的正常人形角色。近战应通过清晰的左右攻击侧和走位产生空间选择，每种武器则应以独有的连击节奏和效果形成手感差异。

## Solution

将初始“人”重新设计为中性年轻游侠，采用轻度俯视的三分之二侧身纸偶。角色根据鼠标相对自身的水平位置在左右之间镜像，移动方向不改变朝向。近战武器只攻击当前左侧或右侧，不追踪正上与正下的目标；玩家需要通过移动把敌人纳入攻击侧。远程技能继续使用全方向瞄准。

建立由武器拥有的连击定义。玩家逐次点击并在输入窗口内续接招式，不按住自动完成连击。初始短刀提供下劈、反向上撩和重横斩三段动作，每段拥有独立时长、范围、伤害、位移和反馈。角色身份、装备和能力继续由汉字语义决定，但角色与装备外形不再强制复现对应字形。

## User Stories

1. As a 玩家, I want 角色以稳定的侧身轮廓展示, so that 我能立即判断角色面对左侧还是右侧
2. As a 玩家, I want 鼠标左右位置控制角色朝向, so that 转身攻击符合我的直接操作意图
3. As a 玩家, I want 鼠标接近角色中线时朝向保持稳定, so that 角色不会在左右之间快速抖动
4. As a 玩家, I want 移动方向与攻击侧独立, so that 我可以边后退或纵向走位边准备攻击
5. As a 玩家, I want 单次招式期间锁定攻击侧, so that 挥刀中途不会因为鼠标移动而突然镜像
6. As a 玩家, I want 连击的下一招可以重新选择攻击侧, so that 我能在招式衔接时转身应对另一侧敌人
7. As a 玩家, I want 近战只覆盖角色左侧或右侧, so that 攻击区域与侧身动作始终一致
8. As a 玩家, I want 正上和正下成为近战盲区, so that 走位与敌人排列对近战战斗有实际意义
9. As a 玩家, I want 斜上和斜下的敌人仍能落入侧向扇区, so that 我不需要与敌人进行像素级水平对齐
10. As a 玩家, I want 远程技能继续全方向瞄准, so that 近战站位限制不会错误地限制火球等能力
11. As a 玩家, I want 每次点击只触发一段攻击, so that 我可以控制是否继续完成整套连击
12. As a 玩家, I want 在当前招式后半段缓存下一次输入, so that 快速操作不会因动画尚未结束而丢失
13. As a 玩家, I want 挥空后仍可续接连击, so that 连击节奏不依赖必须命中敌人
14. As a 玩家, I want 超时后连击回到第一招, so that 每次重新起手都有可预测的动作
15. As a 玩家, I want 翻滚能够在开放取消窗口后中止攻击, so that 我能以放弃连击为代价躲避危险
16. As a 玩家, I want 受击会中止并重置连击, so that 敌人的打断效果清楚且一致
17. As a 玩家, I want 第一刀快速从侧上方向侧下方劈出, so that 短刀拥有清楚直接的起手
18. As a 玩家, I want 第二刀利用第一刀收势反向上撩, so that 连续动作看起来连贯而不是重复播放同一刀
19. As a 玩家, I want 第三刀带有前踏、宽斩和更强击退, so that 完成整套连击有明确回报
20. As a 玩家, I want 第三刀伤害高于前两刀, so that 承担较长动作时间具有战术价值
21. As a 玩家, I want 每段攻击可以命中扇区内多个敌人, so that 短刀仍能处理成群目标
22. As a 玩家, I want 同一招不会对同一敌人重复结算, so that 伤害不受帧率或特效采样次数影响
23. As a 玩家, I want 墨迹真实跟随刀尖运动, so that 特效增强挥刀而不是代替角色动作
24. As a 玩家, I want 三段墨迹具有不同方向与重量, so that 我能从画面识别当前连击阶段
25. As a 玩家, I want 刀柄在所有姿势中始终连接手掌, so that 武器不会像独立物体一样漂浮或旋转
26. As a 玩家, I want 身体、肩、肘和腕依次带动短刀, so that 挥刀具有正常人的传力关系
27. As a 玩家, I want 行走时双腿和远侧手臂有清楚步态, so that 角色不会像一张图片在地面滑动
28. As a 玩家, I want 待机、翻滚、受击和死亡都使用同一套侧身骨架, so that 角色在不同状态间保持视觉连续性
29. As a 玩家, I want 新外形保持约 72–76 逻辑像素高, so that 战场比例与现有走位空间保持一致
30. As a 玩家, I want 角色碰撞半径保持不变, so that 外形更新不会暗中改变闪避与受击距离
31. As a 玩家, I want 初始角色仍以“人”作为规则身份, so that 现有角色成长和汉字主题能够延续
32. As a 玩家, I want “人”的外形是正常游侠而不是人字躯干, so that 动作清楚且人物看起来自然
33. As a 玩家, I want 汉字通过能力、装备和效果表达含义, so that 游戏保留汉字主题而不牺牲美术质量
34. As a 内容设计者, I want 每种近战武器拥有独立的连击定义, so that 长枪、锤和其他武器能形成不同手感
35. As a 内容设计者, I want 连击定义包含招式数量、时长、输入窗口、范围、伤害、位移和效果, so that 新武器无需复制短刀逻辑
36. As a 美术制作者, I want 先确认完整角色和三段动作参考再制作拆件, so that 所有部件共享一致身份、比例和视角
37. As a 美术制作者, I want 只制作右朝向素材并由运行时镜像, so that 素材数量保持可控
38. As a 美术制作者, I want 每个关节和刀柄都有经过组合验证的锚点, so that 程序动作不会暴露断肢或脱手问题
39. As a 开发者, I want 通过完整战斗场景验证连击, so that 输入、动画、判定和反馈作为一个玩家流程被检查
40. As a 开发者, I want 桌面和窄屏截图都纳入回归, so that 角色、短刀与 UI 在实际缩放下保持可读

## Implementation Decisions

- 汉字语义与视觉字形解耦。汉字继续决定角色身份、装备类别、能力和主题；角色、装备与特效不必复现对应汉字的轮廓。初始“人”保留规则身份与 UI 名称。
- 初始角色从零设计为中性年轻成年游侠，约 4 头身，采用国风水墨纸偶风格、紧凑短打衣裤、布靴和束发。设计不需要继承旧角色的头脸、服装、配色或“人”字身体。
- 角色采用轻度俯视的三分之二右侧身。运行时镜像完整视觉容器获得左朝向，不制作第二套左朝向素材。
- 角色运行时由九个透明素材层组成：远侧腿、远侧手臂、躯干、头部、近侧腿、持刀上臂、持刀前臂、手掌和独立短刀。地面影与视觉效果由程序单独绘制。
- 所有部件使用统一的 256 × 256 RGBA 画布和角色根坐标。最终髋、肩、肘、腕、握点与刀柄锚点以获批角色参考图实测，不复用旧人字角色坐标。
- 角色游戏内可见高度保持约 72–76 逻辑像素，逻辑碰撞半径保持 27px。
- 鼠标位于角色右侧超过 20px 时角色朝右，位于左侧超过 20px 时角色朝左。中线左右各 20px 为死区，死区内保持当前朝向。移动方向不参与朝向计算。
- 每一招开始时读取并锁定攻击侧。鼠标在招式期间跨过中线不会翻面；下一招开始时可以按当前鼠标位置转身。
- 近战命中扇区只以正左或正右为中心，鼠标纵向位置不改变挥刀轨迹与判定中心。正上与正下是近战盲区。
- 左右攻击侧适用于所有近战武器。每种武器可以配置不同的招式轨迹、宽度与距离。火球及未来远程武器、投射物和法术保留各自的全方向瞄准。
- 武器拥有连击定义，角色动作系统消费当前武器的招式序列。连击定义至少提供招式时长、命中时点、输入窗口、取消窗口、攻击距离、扇区角度、伤害、移动倍率、位移、击退与反馈强度。
- 每次点击只请求一招，不支持按住鼠标自动完成连击。当前招式进度达到约 60% 后开放下一招输入与翻滚取消；输入窗口中的点击缓存到当前招式结束。
- 挥空可以续接下一招。两招衔接间隔超过 450ms，或发生翻滚、受击、死亡、切换武器时，连击重置到第一招。
- 初始短刀为三段连击。第一刀持续 260ms，从侧上方向侧下方斜劈；判定为 112px、120°、1 点伤害，移动速度为正常的 55%。
- 第二刀持续 230ms，利用第一刀收势从侧下方向侧上方反向上撩；判定为 104px、100°、1 点伤害，移动速度为正常的 55%。
- 第三刀持续 360ms，锁定当前攻击侧前踏并完成宽重横斩；判定为 126px、140°、2 点伤害，拥有更强击退和轻微镜头震动。
- 每招约在自身进度 55% 时进入有效帧并只结算一次。单招可以同时命中多个敌人，但同一招对同一敌人最多造成一次伤害。
- 待机持刀位为斜向前下、手肘微弯。第一刀先经过短提刀预备；第二刀从第一刀收势自然反向；第三刀由前踏和躯干转动带动肩、肘、腕与短刀。
- 每招的全身关键姿势归属武器连击定义，包含身体高低、躯干、肩、持刀上下臂、刀、空手臂和双腿；角色表现模块只负责在姿势间插值。攻击阶段不再使用只由刀角和握点反推肘部形状的通用 IK。
- 第一刀使用由上到下的细墨弧，第二刀使用由下到上的短墨弧，第三刀使用更宽更重的横向墨痕。墨迹采样实际刀尖轨迹并约在 140ms 内消散，不使用独立实心半圆代替挥刀。
- 第一、二刀使用命中闪烁和短暂停顿反馈。第三刀额外使用更强击退与轻微镜头震动。
- 待机、移动、翻滚、受击和死亡全部适配新侧身骨架，但保留现有状态时长、移动规则、翻滚无敌窗口、受击规则和死亡流程。
- 素材生产分为两个门槛：先由 AGY 生成完整右侧身中立姿势与三段短刀动作参考；角色身份获批后，再生成九个透明拆件并人工校正锚点。不得一次生成 spritesheet，也不得把短刀烘焙进手臂或手掌。
- 新九层侧身角色通过运行时验收后，删除旧正面角色、旧侧面参考、旧人字部件和旧图集，避免过时素材继续被误用。
- 战斗场景负责把鼠标输入转换为攻击侧、启动或缓存连击、在有效帧结算命中并绘制命中反馈。角色表现模块负责朝向锁定、连击阶段、纸偶姿势、刀尖轨迹和动作状态过渡。

## Testing Decisions

- 只使用一个浏览器级战斗场景回归接缝。测试启动真实游戏与完整战斗场景，通过鼠标和键盘输入驱动角色，并结合外部可见状态、场景结果与截图验证行为。
- 好测试关注玩家可观察的行为：角色何时翻面、点击是否续招、敌人是否受击、盲区是否不命中、翻滚是否打断、刀与手是否保持连接、画面在目标视口是否可读。测试不锁定私有函数、局部变量名或具体插值公式。
- 画布无法稳定暴露的连击阶段、单招命中次数和锚点距离，沿用现有浏览器脚本的场景测试钩子读取；这些读数只用于确认外部行为，不为低层实现建立第二套测试入口。
- 朝向用例覆盖：鼠标在左右两侧时正确镜像；进入 20px 中线死区时保持朝向；移动不改变朝向；单招中途跨线不翻面；下一招可以转身。
- 连击用例覆盖：逐次点击进入三段；未点击不会自动续招；输入窗口内的点击会缓存；挥空可续招；超过 450ms 后回到第一刀；翻滚与受击会重置。
- 命中用例覆盖：三段分别使用约定的左右扇区与距离；正上、正下目标不受短刀伤害；扇区内多个敌人可同时受击；同一招不会重复伤害同一敌人；第三刀造成 2 点伤害和更强击退。
- 远程回归覆盖：火球仍能向鼠标任意方向发射，不受近战攻击侧限制。
- 动作连接用例覆盖：三段关键帧中手掌握点与刀柄保持连接；肩、肘和腕在招式间确实发生相对运动；左右镜像后层级与连接仍正确。
- 视觉回归覆盖：右侧与左侧待机、三段关键帧、移动、翻滚、受击和死亡；桌面 1280 × 900 与窄屏视口都需截图检查。画布像素检查应确认角色区域非空、没有异常矩形底，并且角色与 UI 不重叠。
- 构建检查作为交付门槛，确保类型检查与生产构建通过。
- 测试先例是仓库现有的浏览器角色验证脚本：它已能启动真实场景、安装测试钩子、检查有效帧与握点距离并生成桌面、移动端和攻击序列截图。新回归应在这一接缝上扩展并替换过时的正面与全方向攻击断言。

## Out of Scope

- 本规格不设计或实现短刀之外的新武器、连击动作与素材，只提供未来武器所需的连击配置能力。
- 本规格不改变火球及其他远程能力的瞄准、伤害和冷却规则。
- 本规格不重新平衡敌人生命值、数量、生成节奏或区域难度；短刀数值可在完成后通过试玩另行调整。
- 本规格不修改角色碰撞半径、基础移动速度、翻滚无敌窗口、受击时长或死亡结算流程。
- 本规格不要求角色、装备或特效重新加入汉字字形元素。
- 本规格不保留旧角色的外貌身份，也不要求新素材兼容旧关节锚点。
- 本规格不采用逐像素刀刃碰撞，命中仍使用每招配置的距离与扇区。
- 本规格不支持按住攻击键自动完成连击。
- 本规格不制作完整 spritesheet；运行时继续使用模块化纸偶部件。

## Further Notes

- 本规格遵循“汉字语义与视觉字形解耦”以及“侧身角色与左右近战攻击侧”两项已接受决策。旧的鼠标全方向近战扇区已经被取代，其余受击、翻滚、掉落和区域节奏规则继续有效。
- 美术验收优先顺序为：正常人体与动作可读性、关节和刀柄连接、游戏尺寸轮廓、风格一致性、细节纹理。
- AGY 参考图必须先通过人工视觉确认，随后才能生产透明拆件。拆件完成后还需要在统一画布中人工校正锚点，不能直接把生成结果当作运行时资产。
- 第一版数值是试玩起点。调整时应维持三段的相对角色：第一刀是快速起手，第二刀是更快的反向衔接，第三刀是更慢但范围、伤害和击退更高的终结招。
